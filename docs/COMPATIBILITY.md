# Compatibility contract for 0.3.0

0.3.0 is a pre-1.0 release with a bounded compatibility promise. The audit recommends a minor release and defers a broad production-stability claim; source-level behavior below is not native/gameplay certification. (`odd/tasks/cycle-2026-11-01-release-audit.md:81`, `odd/tasks/cycle-2026-11-01-release-audit.md:86`)

## Supported surfaces and limits

| Surface | 0.3.0 behavior and promise | Limit / recovery |
| --- | --- | --- |
| Existing project databases | Opening or reopening runs the same schema initialization. Migrations add missing structures in an immediate transaction; failure rolls schema changes back. (`crates/core/src/database/connection.rs:12`, `crates/core/src/database/connection.rs:100`, `crates/core/src/database/schema.rs:14`, `crates/core/src/database/schema.rs:233`) | Supported migration covers the older schemas recognized by this implementation, not arbitrary/corrupt databases. Legacy `injected_files` tables missing expected columns are dropped; the next injection rebuilds those recordings. This is not a promise to preserve all historical cache records. (`crates/core/src/database/schema.rs:15`, `crates/core/src/database/schema.rs:33`) |
| Database downgrade | **Unsupported.** The initializer provides forward/schema-presence migrations; it has no reverse migration or explicit newer-version refusal gate. Do not claim that an older executable safely refuses every newer DB. (`crates/core/src/database/schema.rs:8`, `crates/core/src/database/schema.rs:151`, `crates/core/src/database/schema.rs:192`) | Before first opening with 0.3.0, retain a consistent pre-upgrade checkpoint. Restore that checkpoint with the older binary; do not reopen the migrated working DB to attempt a downgrade. The snapshot implementation includes committed WAL data via `VACUUM INTO`. (`crates/core/src/database/connection.rs:84`) |
| Locust patch manifest | ZIP root `locust-patch.json`, `schema_version: 1`. The optional `game` identity may be absent. (`crates/core/src/patch/manifest.rs:7`, `crates/core/src/patch/manifest.rs:19`, `crates/core/src/patch/manifest.rs:60`) | Any version other than 1 returns `unsupported patch manifest schema <n>`. Apply stages/validates before changing game assets, installed-patch rollback state or receipts; the schema error is returned before force gates, so `--force` cannot override it. Temporary staging may already exist. (`crates/core/src/patch/verify.rs:487`, `crates/core/src/patch/apply.rs:121`, `crates/core/src/patch/apply.rs:154`) |
| Manifest-less / structural patches | A separate legacy path exists; CLI requires explicit `--confirm-legacy` for legacy or structural-tier use. This is not unknown-schema compatibility. (`crates/cli/src/main.rs:230`) | A manifest-less overlay over an installed Locust patch is refused; roll back first. (`crates/core/src/patch/apply.rs:106`) |
| HTTP API | Local desktop/CLI integration, currently unversioned `/api/...` routes. Default listeners are loopback and guarded by Host/Origin checks. (`crates/server/src/lib.rs:582`, `crates/server/src/lib.rs:566`, `crates/server/src/lib.rs:662`) | No public hosted-service or cross-minor API/JSON stability promise. Pair clients with their matching release; never publish Axum through a reverse proxy or Cloudflare Tunnel. (`odd/tasks/cycle-2026-11-01-release-audit.md:165`, `odd/tasks/cycle-2026-11-01-release-audit.md:167`) |
| CLI flags | The shipped Clap command definitions and documented examples define the 0.3.0 interface, including `apply <game> [zip] --url`, `--force`, `--confirm-legacy` and `--dry-run`. (`crates/cli/src/main.rs:28`, `crates/cli/src/main.rs:218`, `README.md:225`) | No blanket cross-minor flag/default or human-output stability guarantee before 1.0. Pin automation to a release and review its help/notes before upgrading. Existing flags do not override hard archive/schema safety errors. (`odd/tasks/cycle-2026-11-01-release-audit.md:86`, `crates/core/src/patch/verify.rs:487`) |

Database checkpoints, game injection backups and patch rollback are different recovery mechanisms. Restoring application binaries or an updater manifest does not reverse project migrations or game writes. Patch rollback restores the patch store's originals; injection backups have their own restore workflow. (`crates/core/src/database/connection.rs:84`, `crates/cli/src/commands/patch.rs:351`, `README.md:374`, `RELEASE.md:121`)

## Stable and Experimental formats

The implementation defines **Stable** as extensively tested/reliable and **Experimental** as working with known edge cases or limited testing. Stability is a plugin label, separate from application versioning or certification of every game, engine revision, font or save file. The trait defaults to Stable. (`crates/core/src/extraction.rs:17`, `crates/core/src/extraction.rs:100`, `odd/tasks/cycle-2026-11-01-release-audit.md:83`)

- **Stable:** RPG Maker MV/MZ; RPG Maker XP/VX/VX Ace; Ren'Py. Supported-container and partial-extraction limits still apply. (`README.md:34`, `README.md:42`)
- **Experimental:** SugarCube/Twine, generic HTML, Unity, Unreal, Wolf RPG, VNTextPatch JSON, QSP, TyranoBuilder, KiriKiri/KAG, YU-RIS, NScripter/ONScripter and Godot/Dialogic. Coverage is bounded by fixtures/sample games and each format's documented profile. Godot 4.4/v3 profiles have synthetic coverage without verified real-game/engine launch. (`README.md:51`, `README.md:66`)

## Conditions for a future 1.0

Reserve 1.0 for named supported engines/platforms, native installer and older-install updater proof, representative gameplay checks, and documented API/data upgrade, downgrade and rollback boundaries. Experimental plugins may remain if their limits are explicit; their existence alone does not indefinitely prevent 1.0. (`odd/tasks/cycle-2026-11-01-release-audit.md:86`)

**Owner input needed:** choose that bounded support matrix and supply native platform/older-installation access and representative test games with permission to use them; approve the compatibility policy after the acceptance evidence exists. Current release acceptance requires exact-candidate CI and native updater outcomes, not just generated JSON or headless UI checks. (`odd/tasks/cycle-2026-11-01-release-audit.md:41`, `odd/tasks/cycle-2026-11-01-release-audit.md:86`, `RELEASE.md:117`)
