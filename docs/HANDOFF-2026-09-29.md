## Traps found this session

- **Shell quoting:** an unquoted or even quoted heredoc containing backticks/apostrophes broke bash twice (cycle 98 launch, `unexpected EOF`); nothing had started. Write briefs with the file-writing tool and launch Codex with a short command (`nohup codex exec ... - < brief.md > log 2>&1 &`).
- **Codex sandbox:** `[windows] sandbox = "elevated"` in `~/.codex/config.toml` makes some shell reads hang for ~170 s; `unelevated` answered in 20 s (another agent's finding, 2026-09-29). Not changed here because the suite-wide `writable_roots` setup was validated under elevated. If stalls return, try `-c windows.sandbox="unelevated"` per call and rerun the full suite first. A trivial probe needs `</dev/null` or codex waits on stdin.
- **`codex update` on Windows failed** in the user's pwsh 7 session: the child Windows PowerShell 5.1 inherits pwsh 7's `PSModulePath`, so `Get-FileHash` disappears. Fix: `$env:PSModulePath = "$env:WINDIR\System32\WindowsPowerShell\v1.0\Modules"; codex update`.
- **`docs/IMPROVEMENT-GOAL.md` has MIXED line endings** (mostly LF, ~35 CRLF, and a few stray CR characters inside old entries). Do NOT split it by `\r\n`, by `splitlines()` or with multi-line perl; split on `\n` only, delete or insert whole physical lines, and check `git diff --stat` (a wrong edit once looked like +37/-67 for a 3-line change).
- **Ledger perl edits:** a replacement string containing `\\r` inserted a real CR. Prefer the Edit tool or a Python script that works on `\n`.
- Background launcher notifications ("Background command ... completed") only mean the shell exited; the Codex process keeps running. Judge by the log and `git status`.
- Codex researchers may write scratch files but must not touch the repo or `D:\juegos`; verify with `git status --short`.
