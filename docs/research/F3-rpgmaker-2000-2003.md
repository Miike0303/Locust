**Format background — my format knowledge, checked against EasyRPG/liblcf**

LCF uses signatures such as `LcfDataBase`, `LcfMapTree` and `LcfMapUnit`. Structured fields generally contain BER-style integer chunk ID, byte length and payload. Integers accumulate seven-bit groups most-significant first; this is not LEB128. Nested record arrays contain counts and record IDs. Framing is type-specific, including terminator exceptions. See liblcf’s [integer reader](https://github.com/EasyRPG/liblcf/blob/master/src/reader_lcf.cpp) and [structure implementation](https://github.com/EasyRPG/liblcf/blob/master/src/reader_struct_impl.h).

Player-visible text includes:

- **LDB:** actor names/titles; skill/item names and descriptions; enemy/state/class names; UI terms, skill-use/battle messages; common-event and troop battle-event dialogue.
- **LMU:** event-page commands `10110` and continuation `20110` carry message lines. `10140` starts choices; labels reside in `20140` branch commands, ending at `20141`. Preserve indentation, branch indices and cancellation parameters. See the [Player interpreter](https://github.com/EasyRPG/Player/blob/master/src/game_interpreter.cpp).
- **LMT:** map names, visible in teleport selection; **INI:** optional `GameTitle`. EasyRPG’s [translation guide](https://easyrpg.org/player/guide/game_translation/) identifies these translation domains.

Event commands serialize code, indentation, string byte length/string, parameter count/parameters; lists end with four zero bytes. Lengths are recalculated on write, allowing translations to grow. Update enclosing chunk lengths and associated event-command-size fields too ([command serializer](https://github.com/EasyRPG/liblcf/blob/master/src/ldb_eventcommand.cpp), [page schema](https://github.com/EasyRPG/liblcf/blob/master/src/generated/lmu_eventpage.cpp)). Display limits remain separate.

Japanese games commonly use CP932/Shift-JIS; other releases use Western/CJK code pages. EasyRPG accepts `[EasyRPG] Encoding=1252` in `RPG_RT.ini`; command-line encoding overrides it ([manual](https://easyrpg.org/player/manual/)). This key does not establish original RPG_RT compatibility.

**Options**

A bounded native Rust parser/writer offers precise preservation: retain original spans, decode whitelisted fields, and rebuild only affected structures. Preserve opaque chunks byte-identically, ordering, untouched fields and original integer encodings wherever possible.

An external [lcf2xml](https://github.com/EasyRPG/liblcf/blob/master/tools/lcf2xml.cpp) bridge supplies broad schema coverage but adds executable deployment, version, engine and encoding configuration. Unknown-byte preservation is unsafe to assume: liblcf [skips unrecognized fields](https://github.com/EasyRPG/liblcf/blob/master/src/reader_struct_impl.h). Use it as an independent semantic oracle.

**Recommendation**

Choose native Rust with explicit supported-subset diagnostics and signature-based detection. Use structural locators—file/record/event/page/command index—plus source-byte verification.

Keep one declared game encoding. Spanish `á`, `é`, `ñ`, `¿` are unrepresentable in ordinary CP932. Reject unmappable translations without substitution. CP1252 or EasyRPG UTF-8 requires a deliberate game-wide migration considering Japanese strings, resource filenames and fonts; changing the INI alone is insufficient.

**First unit**

Deliver read-only extraction of LMU messages/choices and LDB actor/skill/item names, plus an internal lossless round-trip serializer. Return no supported output modes and explicitly reject injection initially. Defer LMT, descriptions, terms, common/battle events and INI writes.

Generate tiny synthetic fixtures in tests, without game assets. Acceptance checks:

- Exact extracted text and deterministic structural IDs; exclude filenames/comments.
- Byte-identical untouched round trips, including unknown nested chunks and noncanonical integer encodings.
- Bounded rejection of truncated/overflowing BER, invalid lengths/counts and malformed command lists.
- Incomplete-folder diagnostics preserve saved rows.
- Before enabling reinjection: growth/shrink across BER boundaries, updated size fields, unchanged command semantics, encoding rejection, independent liblcf parsing, Replace containment and Direct revision/recovery checks.
